## 개선 원칙
- 원본 프롬프트의 **의도와 목적을 변경하지 마세요**
- 모호한 표현을 구체적 기준으로 교체하세요
- 누락된 제약 조건을 추가하세요
- 구조를 개선하되 과도하게 복잡하게 만들지 마세요
- 각 수정에 대해 **왜 이렇게 바꿨는지** 근거를 남기세요

## 개선 기법 체크리스트
- [ ] 역할(Role) 명확화: 구체적 전문 분야, 경력, 관점 포함
- [ ] 지시(Instruction) 구조화: 번호 매기기, 우선순위 지정
- [ ] 맥락(Context) 보강: 배경 정보, 제약 조건 추가
- [ ] 출력 형식(Format) 명시: 마크다운 구조, 섹션, 길이 제한
- [ ] 예시(Few-shot) 추가: 필요한 경우 입력-출력 예시 포함
- [ ] 부정 지시(Negative prompt) 추가: "하지 말아야 할 것" 명시
- [ ] 단계별 사고(Chain-of-thought) 유도: 필요한 경우 추론 단계 지정
